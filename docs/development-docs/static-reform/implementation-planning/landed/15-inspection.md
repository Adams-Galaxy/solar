## 1. Objective

Land a narrow generic discovery and query layer over facts already owned by the
System graph, Lifecycle, Execution, Metrics, and Remote. Inspection had to let
local code and an unfamiliar Remote host enumerate selected system surfaces,
page records with bounded cost, and format supported values without creating a
universal snapshot, copied histories, or another runtime authority.

## 3. Public Surface Landed

The aggregate header is `solar/inspection.hpp`, included by `solar/solar.hpp`
when `CONFIG_SOLAR_INSPECTION=y`.

The public vocabulary includes:

- `inspection::Descriptor`, `DescriptorView`, `Id`, and `LocalId`;
- collection metadata for subsystem, capabilities, consistency,
  synchronization, context, and query cost;
- `Cursor`, `PageRequest`, `PageResult`, freshness, loss, and focused errors;
- the `inspection::CollectionType` concept;
- the `inspection::Provider<Collection>` customization point;
- `inspection::Collections<...>` and the conventional `using Inspections`
  contribution alias;
- `inspection::Of<Application>` plus default-bound free functions;
- bounded `collections`, `describe`, `find`, `visit`, and `query` operations;
- bounded `format_text` and deterministic `encode_cbor` helpers;
- `TextFormatter<Record>` and `CborEncoder<Record>` extension points.

The built-in collection set is selected from enabled capabilities:

- `inspection::Components`;
- `inspection::LifecycleComponents`;
- `inspection::ExecutionRegistrations` when Execution is enabled;
- `inspection::MetricValues` when Metrics is enabled;
- `inspection::RemoteLinks` when Remote is enabled.

Representative application extension:

```cpp
struct Samples
{
    using Record = SampleRecord;
    using Query = solar::inspection::BasicQuery;

    static constexpr solar::inspection::Descriptor descriptor{
        .name = "navigation.samples",
        .stable_id = solar::inspection::Id{0xF1700001U},
        .maximum_page = 8,
        .record_size = sizeof(Record),
        .query_size = sizeof(Query),
    };
};

struct Navigation
{
    using Inspections = solar::inspection::Collections<Samples>;
    static constexpr solar::component::Descriptor descriptor{.name = "navigation"};
};

template <> struct solar::inspection::Provider<Samples>
{
    static solar::Result<solar::inspection::PageResult,
                         solar::inspection::Error>
    query(const Samples::Query&, std::span<Samples::Record>) noexcept;
};
```

Ordinary query:

```cpp
std::array<solar::lifecycle::ComponentRecord, 8> records{};
auto page = solar::inspection::query<
    solar::inspection::LifecycleComponents>(
        {.page = {.limit = records.size()}}, records);
```

## 4. Runtime Ownership

| Owner | Storage/resource | Capacity | Synchronization | Lifetime |
| --- | --- | --- | --- | --- |
| Inspection catalog | immutable descriptor views | `CONFIG_SOLAR_INSPECTION_MAX_COLLECTIONS` compile-time ceiling | none | image lifetime when odr-used |
| Local caller | query output records | caller-supplied span | provider-defined while copying | call/caller lifetime |
| Remote service per link | shared discovery/query encoding scratch | `CONFIG_SOLAR_INSPECTION_REMOTE_RESPONSE_BYTES`, default 1024 bytes | serialized Remote service handling | image lifetime |
| Remote provider per System/collection | typed query page records | `CONFIG_SOLAR_INSPECTION_REMOTE_MAX_PAGE_RECORDS`, default 8 records | serialized Remote service handling; source synchronization remains provider-owned | image lifetime when Remote query support is instantiated |

The Inspection Facility owns no mutable state, heap allocation, thread, stack,
workqueue item, timer, poll object, lock, or copied history. Its lifecycle hooks
only report successful participation as a passive built-in.

All canonical state remains with its source subsystem. Providers acquire or
copy source data according to that subsystem's synchronization contract and
release source locks before text/CBOR formatting or Remote transmission.

No constructor registration or cross-translation-unit static initialization
is used. Catalogs and buffers are type-owned static storage.

## 5. Compile-Time Behavior

`inspection::Tag` participates in the generic catalog set. Enabled built-in
collections are added as direct built-in declarations; user collections flow
through ordinary component contributions and preserve semantic owner and
origin.

Each collection must provide bounded `Record` and `Query` types plus an exact
Inspection descriptor. A reusable catalog-traits declaration-validation hook
was added because descriptor validation alone cannot prove the nested record
and query contract. Binding rejects malformed collections before descriptor
materialization.

Stable IDs are mandatory and unique in the Inspection identity domain.
Effective collection count is checked against
`CONFIG_SOLAR_INSPECTION_MAX_COLLECTIONS`. Remote response and page ceilings
are checked against the local Inspection and Remote message ceilings.

Strict and relaxed application bindings expose the same typed operations.
Inspection itself adds no relaxed-mode dispatch table because all collection
types and providers are resolved from the bound System at compile time.

When Inspection is disabled, its built-in collection list and Facility are
absent and the effective catalog must be empty. Direct subsystem APIs remain
available.

Stable diagnostic contracts cover:

- `SOLAR_DIAGNOSTIC_INVALID_INSPECTION_COLLECTION`;
- `SOLAR_DIAGNOSTIC_INSPECTION_PROVIDER_MISSING`;
- `SOLAR_DIAGNOSTIC_INSPECTION_COLLECTION_NOT_REGISTERED`;
- `SOLAR_DIAGNOSTIC_INSPECTION_COLLECTION_CEILING`;
- Remote page and response ceiling violations.

## 6. Error And Availability Behavior

Inspection returns `Result<T, inspection::Error>`. `Error` retains operation,
collection identity, focused reason, Solar status, and optional detail.

- `Disabled`: a formatting capability was compiled out.
- `Unsupported`: a record lacks the requested formatter/encoder or a provider
  cannot support the requested operation.
- `Unavailable`: canonical source state is not ready, such as Metrics before
  its owning System boots.
- `Busy`: the source reports `Busy` or `WouldBlock`.
- `NotFound`: local/stable collection identity is unknown.
- `StaleCursor`: a cursor is reused against another collection.
- `InvalidRequest`: malformed offsets or source query values.
- `NoSpace`: a requested page exceeds its collection ceiling, or encoding
  cannot fit the caller's buffer.
- `SourceFailed`: a source failed without a more focused mapping.

A query's returned cursor is normalized to the concrete collection if a custom
provider omits it. Providers that claim to have written beyond the supplied
span are rejected as source failures.

Remote requires the existing Observe grant. Wire errors distinguish unknown
targets, not ready, busy, capacity, decode failure, and internal failure.

## 7. Zephyr Integration

Inspection is Zephyr-native through Solar's normal module Kconfig and effective
Blueprint inclusion. It does not call a Zephyr kernel API directly. Canonical
providers reuse the source subsystem's established Zephyr synchronization and
records.

Relevant Kconfig is:

- `CONFIG_SOLAR_INSPECTION`;
- `CONFIG_SOLAR_INSPECTION_MAX_COLLECTIONS`;
- `CONFIG_SOLAR_INSPECTION_MAX_PAGE_RECORDS`;
- `CONFIG_SOLAR_INSPECTION_TEXT_FORMATTING`;
- `CONFIG_SOLAR_INSPECTION_CBOR`, dependent on canonical zcbor support;
- `CONFIG_SOLAR_INSPECTION_REMOTE`;
- `CONFIG_SOLAR_INSPECTION_REMOTE_MAX_PAGE_RECORDS`;
- `CONFIG_SOLAR_INSPECTION_REMOTE_RESPONSE_BYTES`.

Remote collection discovery uses a compact fixed binary descriptor page.
Collection records use deterministic, definite-length CBOR. The host Python
SDK decodes collection descriptors and typed `CollectionQueryPage` metadata
and can issue discovery or query requests through `Client.introspect`.

Collection descriptors declare required context and whether a provider may
block. No ISR-capable collection is currently advertised beyond immutable
component descriptors; callers must obey the declared context.

None. The declaration-validation hook and shared Remote scratch buffer are

## 11. Firmware And Host Impact

Firmware does not need to name Inspection in its System graph. Enabling
`CONFIG_SOLAR_INSPECTION` selects the passive built-in and standard collections;
enabling its Remote option advertises collection capability during Remote
hello and activates host discovery/query.

The in-tree Python host SDK gained collection request, query request,
descriptor page, and collection-page support. Existing protocol operations and
generated Remote manifests are unchanged.

## 12. Known Limits And Deferred Work

- Built-in collections intentionally cover only canonical records already
  landed. Hardware, Health, and Supervisor can add focused providers in their
  owning stages.
- Arbitrary custom Remote collections require `BasicQuery`, a deterministic
  `CborEncoder<Record>`, and an explicit Remote capability bit.
- Text formatting is record-specific; unsupported record types return a
  focused error.
- Inspection has no filter language, history store, universal snapshot, or
  hidden coordination thread by design.

## 13. Documentation Handoff
